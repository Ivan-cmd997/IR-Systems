# IR Systems — сайт

Статика: HTML + CSS + один небольшой скрипт. Ни фреймворков, ни сборщика, ни
внешних запросов — всё, что грузит страница, лежит в этой папке.

## Запуск

```bash
python -m http.server 4173
```

Открыть <http://localhost:4173>. Деплой — залить папку как есть на Netlify,
Vercel или GitHub Pages, никакой сборки не требуется. `index.html` — стартовая
страница на любом статическом хостинге, менять ничего не нужно.

## Что где

```
index.html          публичный сайт: блоки 01–07, синяя тема, анимация появления — сюда идут клиенты
guideline.html       внутренний документ: та же витрина + гайдлайн по идентике (08–14) — для Ивана
css/tokens.css       @font-face и :root — единственный источник цветов и размеров
css/theme-blue.css   переопределяет 7 цветовых токенов для index.html, размеры не трогает
css/style.css        вёрстка и компоненты, общие для обеих страниц
js/main.js           копирование hex из палитры + появление блоков при скролле
fonts/*.woff2        Onest, Golos Text, JetBrains Mono; кириллица и латиница врозь
assets/*.svg         4 версии логотипа, 2 монограммы, 2 фавиконки (красная / синяя)
img/og-blue.png       og-картинка для index.html
img/og.png           og-картинка для guideline.html
robots.txt           вместе с sitemap.xml
```

## Две страницы, одна оболочка

`index.html` — публичный сайт, основной вход для клиентов: только блоки 01–07,
без служебного слоя снизу. Бело-чёрно-синяя тема, анимация появления блоков
при скролле.

`guideline.html` — рабочий документ для Ивана: та же витрина сверху плюс
гайдлайн по идентике снизу (логотип, палитра, типографика, сетка, тон голоса),
красно-графитовая палитра из раздела 2 ТЗ. Закрыт от индексации
(`<meta name="robots" content="noindex, nofollow">`), у него свой canonical на
`/guideline.html` — иначе он спорил бы с `index.html` за одинаковый заголовок и
текст в поиске.

Вёрстка и компоненты — из общих `style.css` и `tokens.css`, поэтому это не два
отдельных сайта, а одна система с двумя темами поверх неё:

- **Палитра** — `css/theme-blue.css` переопределяет всего 7 переменных
  (`--paper`, `--ink`, `--deep`, `--steel`, `--line`, `--infra`,
  `--infra-on-deep`) на бело-чёрно-синие. Размеры, отступы, шрифты и вёрстка
  не меняются ни на пиксель. Логотип в шапке нарисован инлайн-символом с
  заливкой `var(--logo-ink)`/`var(--logo-tick)`, поэтому он сам перекрашивается
  в новую тему — отдельный файл для этого не понадобился.
- **Контраст** пересчитан для новых цветов: `steel` на белом — 4,9:1, синий
  акцент на белом — 8,5:1, светло-синий акцент на тёмном — 6,1:1. Все три с
  запасом проходят AA.
- **Анимация появления.** При загрузке страницы блоки не наваливаются все
  разом: `IntersectionObserver` в `main.js` добавляет класс `.is-visible`
  элементам с классом `.reveal`, когда они входят в область видимости, а
  внутри `[data-reveal-group]` они появляются по очереди — каждый следующий на
  90мс позже предыдущего (максимум 360мс задержки, чтобы группа из многих
  элементов не тянулась). При `prefers-reduced-motion: reduce` — тот же
  принцип, что и у тепловой полосы: анимация отключается, всё показывается
  сразу. Код общий для обеих страниц и не действует на `guideline.html`,
  потому что там просто нет элементов с классом `.reveal`.

## Логотип

Четыре SVG нарисованы не «на глаз»: контуры букв I и R взяты прямо из Onest 800
и переведены в кривые, поэтому файлы рендерятся везде и не тянут шрифт за собой.
Построение — по разделу 3 ТЗ: трекинг −0,04em, риска шириной 1/32 от высоты
прописной (ровно 1px на минимальном размере 120px), отступ до `SYSTEMS` равен
ширине буквы I.

Пересобрать логотипы можно скриптом, который лежит вне репозитория; проще
править SVG руками — они читаемые.

## Тепловая полоса

Единственная анимация первого экрана. Сделана чистым CSS (`@keyframes` +
`clip-path`), без JS: если скрипты отключены, полоса всё равно отрисуется. По
умолчанию она нарисована целиком, анимация добавляется только внутри
`@media (prefers-reduced-motion: no-preference)` — то есть при `reduce`
пользователь сразу видит финальное состояние, как и требует ТЗ.

## Два отступления от ТЗ, о которых надо знать

Раздел 2.1 приводит цифры контраста, которые не сходятся с расчётом по WCAG 2.1.
Проверено на живой странице:

| Пара | В ТЗ | На самом деле | Что сделано |
|---|---|---|---|
| `steel` на `paper` | ~4,6:1 | **4,18:1** — не проходит AA | `--steel` затемнён с `#6B7076` до `#656A70` → 4,6:1 |
| `infra-on-deep` на `deep` | «хватает» | **4,12:1** — не проходит AA | осветлён с `#D4392E` до `#DA453A` → 4,6:1 |

Оба значения подобраны как минимально возможные: оттенок и характер цвета не
изменились, но текст от 12px теперь проходит AA. Без этой правки пункты 6 и 11
ТЗ (Lighthouse 100 по доступности, «контрасты из 2.1») противоречат друг другу.
Если Иван предпочтёт исходные хексы — надо будет отказаться от AA или поднять
минимальный кегль вторичного текста до 24px.

Ещё две мелочи:

- **JSON-LD**: в ТЗ написано `hasOffer`, но такого свойства в schema.org нет.
  Использовано `makesOffer` с тремя `Offer` — валидный эквивалент, иначе разметка
  не прошла бы Rich Results Test.
- **og.png, а не WebP**: пункт 6 требует WebP для всех изображений, но часть
  краулеров соцсетей до сих пор не читает WebP в `og:image`. Картинки для
  шеринга оставлены в PNG сознательно. Все остальные изображения (скриншоты
  работ, фото) — в WebP, разметка под них готова.

## Проверено

На локальном сервере, программно: ошибок в консоли нет, все ресурсы отдают 200,
три шрифта грузятся и применяются, горизонтального переполнения нет ни на 360px,
ни на десктопе, иерархия заголовков без пропусков (один `h1`, дальше `h2`/`h3`),
у всех картинок есть `alt` и заданы `width`/`height`.

Контраст посчитан по WCAG 2.1 для каждого текстового элемента страницы против
его фактического фона: **0 нарушений** на обеих страницах. Все размеры текста
на странице — ровно шесть значений шкалы (12 / 15 / 17 / 22 / 40 / 76 на
десктопе), все цвета — ровно токены из `tokens.css` / `theme-blue.css`.

`index.html` (публичная, синяя тема) проверен тем же способом: 0 нарушений
контраста, 0px переполнения на 360px и десктопе, ровно 6 секций (01–07, без
гайдлайна), один `h1`. Логику reveal-анимации подтвердил вручную: правило
`.reveal.is-visible { opacity: 1 }` побеждает `.reveal` по специфичности CSS
(0,2,0 против 0,1,0), классы расставляются с задержками 0/90/180/270мс внутри
каждой группы — но саму анимацию вживую в этой сессии посмотреть не вышло:
браузерная панель в этой среде держит документ в состоянии `hidden`, а в этом
состоянии Chromium приостанавливает `IntersectionObserver` и рендер-кадры (та
же причина, по которой не получилось снять скриншоты и прогнать Lighthouse).
Откройте `index.html` в обычном браузере и проверьте анимацию и Lighthouse
глазами перед деплоем — это единственное, что осталось непроверенным вживую.
